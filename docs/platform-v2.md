# Эдентика: рабочие сценарии и границы текущей версии

## Пользователи

Регистрация: логин, ФИО, пароль и одна из ролей — методист, эксперт, обучающийся. Старые аккаунты сохраняются, начальный логин совпадает с прежним email. В профиле можно изменить ФИО и логин; роль через профиль не повышается.

Методист создаёт программы, назначает экспертов и обучение группам. Эксперт видит только назначенные ему черновики. Обучающийся видит каталог и свои назначения; API урока не возвращает правильные ответы.

Сейчас роли выбираются при регистрации. Две разные учётные записи не удостоверяют двух разных физических лиц: проверка квалификации экспертов и приглашения организацией пока не реализованы. Публичное копирование подразумевает передачу полного комплекта материалов другому методисту, включая ключи тестов; для защищённой аттестации нужен отдельный закрытый банк вопросов.

## Создание и согласование

1. Методист описывает задачу и добавляет DOCX/PDF/TXT. Перед новой генерацией платформа предлагает похожие публичные курсы без расхода LLM-токенов.
2. Агент уточняет требования, затем готовит каркас. Методист проверяет цель, компетенции, часы и согласует их до генерации материалов.
3. Материалы создаются по модулям. Отдельные уроки и модули можно исправить вручную или предложением из общего чата. Загруженный исправленный документ становится референсом конкретной правки; произвольная Office-вёрстка не переносится дословно.
4. Методист выбирает эксперта. Тот видит компетенции, проверки, материалы, задания, тесты, разделы и источники; оставляет адресные замечания и одобряет конкретный digest содержания.
5. После исправления замечаний методист подтверждает публикацию. Требуются его согласованный каркас, отсутствие ошибок проверки и актуальное одобрение другого аккаунта-эксперта. Любое изменение охваченного digest содержания требует повторной экспертизы.
6. Опубликованный курс — отдельный неизменяемый снимок. Новые правки черновика не меняют обучение текущей группы. Доступ public/private можно изменить отдельно; перевод в private скрывает все версии программы из каталога, сохраняя назначения. Программу с публикациями нельзя окончательно удалить, чтобы не разрушить историю обучения.

Демонстрационные запросы и кнопки примеров удалены из рабочей платформы. Тестовые фикстуры остались только в проверках и отдельном временном UX-стенде.

## Обучение и группы

Публичный курс можно добавить в своё обучение или скопировать в пространство методиста. Урок содержит учебный текст, слайды и, при наличии, тест. Проходной балл — 70%; повторные попытки разрешены, хранится лучший результат. Урок без теста завершается подтверждением прочтения.

Методист создаёт группы, добавляет зарегистрированных обучающихся по логину и назначает собственные опубликованные курсы группе или конкретному участнику со сроком. Статистика показывает завершённые уроки, общий объём уроков, процент прохождения, балл и срок. Это не измерение реального времени внимания и не прокторинг. Организационные приглашения, сложные иерархии организаций, оплаты и сертификаты не входят в текущую реализацию.

## Модели и затраты

Локально сохранён официальный Codex CLI-провайдер с входом через ChatGPT, только на loopback. В Docker сервер работает с Cloud.ru или указанным OpenAI-совместимым шлюзом. По указанию владельца на ВМ включён SYSTEM_LLM_SHARED_ACCESS=1: системная модель доступна всем зарегистрированным методистам. При выключенном флаге действуют SYSTEM_LLM_ALLOWED_USERS либо личное подключение. В настройки профиля можно добавить свой HTTPS API endpoint, модель и ключ. Другие протоколы, в том числе несовместимые с Chat Completions, требуют отдельного адаптера.

Ключи шифруются Fernet с APP_ENCRYPTION_KEY, не возвращаются через API и не передаются Codex-подпроцессу. Сохраните ключ сервера вместе с резервной копией: потеря ключа делает подключения недоступными. HTTPS-запросы к пользовательским endpoint проверяют публичные IP, фиксируют DNS-результат на соединение, проверяют TLS, запрещают redirect и сжатые ответы, ограничивают размер и время.

Экономия: повторное использование публичных программ, кеш ответов в пределах аккаунта, выбор релевантных фрагментов референсов, адресная доработка урока/модуля и мониторинг фактического расхода. Кеш не разделяется между пользователями. Фактические токены берутся из usage ответа поставщика; стоимость рассчитывается только при заданном тарифе. Общий бюджет программы отключён. Платформа также не отправляет фиксированный max_tokens; технические пределы контекста, ответа и квоты определяет поставщик.

## Источники и документы

Поисковая интеграция Brave Search включается BRAVE_SEARCH_API_KEY; без неё платформа получает только явно переданные ссылки и помечает отсутствие поиска. Страницы загружаются ограниченными HTTPS-запросами; полученный текст не доказывает актуальность, нормативную силу или соответствие тезису. Модель показывает причину использования источника и связь с модулем. Финальное решение остаётся за экспертом. Автоматической проверки всех реестров профстандартов нет.

Лекции выгружаются в DOCX/PDF, презентации — в PPTX/PDF. PDF формируется отдельной вёрсткой по тем же данным и может визуально отличаться от Office-файла. Редактирование загруженного DOCX/PPTX через чат переносит извлечённый текст, а не все стили, диаграммы и анимации.

## Проверки

Сценарии покрыты интеграционными тестами на временных PostgreSQL БД; рабочая пользовательская БД не очищается. В Docker тестовый профиль использует отдельный test-db без доступа к production volume и без реальных ключей моделей. Модельные тесты используют управляемые ответы; качество полного курса на реальной модели и целевой SLA каркаса <3 минут нужно измерять отдельно.

UX проверяется через отдельную базу `edentica_ux_*` и порт 3010 (`scripts/preview-workspace.py`). Она не должна публиковаться на ВМ. Скриншоты проверки сохраняются в output/ux-audit. Секретов и ключей в них нет.

Ни один автоматический тест, статический аудит или структурная проверка не подтверждает отсутствие всех уязвимостей или педагогических ошибок.

## Фактический замер

18 октября 2026 года локальный Codex подготовил каркас 16-часовой программы за 126,69 секунды (3 вызова с исправлением результата): 33 244 входных и 5 543 выходных токена. Это единичная проверка, не гарантия времени для всех тематик и объёмов. После неё добавлен объединённый путь разбора и каркаса одним ответом; он проверен отдельным тестом без автоматического согласования.

Одновременные одинаковые запросы одного пользователя объединяются под одним cache key, чтобы не оплачивать повторный вызов. Глобально одновременно выполняется не больше двух запросов к модели, включая чат.

## Развёртывание 18 октября 2026

Обновлённая версия собрана командой Docker Compose на ВМ команды: backend, frontend и PostgreSQL работают и проходят healthcheck. Отдельная test-db остановлена после 33 успешных тестов (9,58 с). Локальные 33 теста прошли за 23,63 с. Минимальный реальный запрос GigaChat-3-Pro выполнен успешно; это проверка соединения, а не качества полного курса.

Внутренний DNS шлюза требует SYSTEM_LLM_ALLOW_PRIVATE_NETWORK=1 только для административного LLM_BASE_URL. Пользовательские подключения сохраняют запрет внутренних сетей. Loopback и link-local адреса запрещены в обоих режимах. Эта настройка не выдаёт пользователям доступ к системной квоте: отдельно нужен SYSTEM_LLM_ALLOWED_USERS либо SYSTEM_LLM_SHARED_ACCESS=1.

Публичный адрес ВМ перенаправляет неавторизованный браузер на страницу входа GIGASCHOOL Hub. Авторизация инфраструктуры не заменяет аккаунт Эдентики. Git-коммиты и отправка кода не выполнялись.

## Повторная проверка ВМ и Gitea

После входа пользователя в GIGASCHOOL Hub переход к публичному демо из кабинета ВМ открывает главную Hub вместо Эдентики. На самой ВМ порт 8000 возвращает HTTP 200 с главной страницей Эдентики, а /api/health — ready/python/postgresql. Внешняя браузерная проверка интерфейса приложения не завершена из-за этого перенаправления.

Реальная генерация через GigaChat-3-Pro проверялась в отдельной временной PostgreSQL БД, которая удалялась после каждого прогона. Выявлены некорректная схема JSON, обрезание ответа и лишние уточняющие вопросы при полном брифе. Добавлены валидация схемы, ограниченный повтор, JSON-режим системного шлюза, лимит 12 000 токенов ответа и запасной разбор без каркаса при обрезании. Проверки на повтор известной аудитории и обрезанный ответ включены в тесты.

После исправлений проходят 36 тестов локально и в Docker на ВМ. Последний реальный прогон завершил разбор, но остался в clarification: модель спрашивает уже заданные параметры теста и аттестации. Поэтому полный сценарий создания каркаса и SLA на GigaChat пока НЕ подтверждены. Успешный минимальный запрос к шлюзу не является проверкой качества программы.

Чистый снимок исходников отправлен в Gitea в ветку dev без прежней истории, баз, журналов и секретов. Ветка main не изменена. Подробности: docs/gitea.md.


## Мониторинг токенов

В профиле доступна отдельная страница «Расход токенов» (#usage): периоды 7/30/90 дней, гистограмма входных и выходных токенов, таблица значений, количество обращений и общий расход аккаунта. День определяется в часовом поясе браузера; API проверяет пояс по справочнику PostgreSQL.

Ограничение суммарного бюджета программы и фиксированные потолки ответа платформы отключены. Сохранённые tokenBudget и output_limit старых записей больше не ограничивают генерацию. Это не отменяет контекстное окно, значения по умолчанию, квоты и ограничения API поставщика.

Журнал llm_usage_events хранит только владельца, программу, модель, навык, время и счётчики, без запросов, ключей или ответов. Он сохраняется при удалении программы. Кеш не создаёт новое платное обращение. Повторы учитываются отдельно. Если получен некорректный или обрезанный JSON с usage, расход также записывается. Если поставщик не передал usage, точное число токенов неизвестно: интерфейс не оценивает его приблизительно.

Прежние счётчики существующих программ один раз сохраняются в llm_usage_baselines. Они входят в общий итог отдельно от дневной гистограммы; достоверные даты задним числом не придумываются. Расход удалённых до запуска журнала программ восстановить невозможно.

Проверки: 40 интеграционных/контрактных тестов, включая отключённый бюджет, отсутствие max_tokens, ошибки модели, кеш, изоляцию аккаунтов, смену часового пояса, сохранение после удаления программы и повторный запуск миграции.

## Повторная проверка доступности ВМ

Публичный адрес https://tochka-sborki-2026-team-074.hub.gigaschool.ru/ теперь открыл Эдентику в браузере с действующей авторизацией Hub. Прежнее перенаправление в этом прогоне не воспроизвелось. Снимок: output/ux-audit/10-vm-public-home.png (локальный диагностический артефакт).

Backend, frontend и PostgreSQL healthy; порт 8000 и /api/health отвечают 200. Хеши 11 активных файлов приложения совпали с локальной версией, usage.js по HTTP также совпадает. Последний контейнерный прогон: 40 тестов.

Для проверки генерации требуется отдельный доступ: серверный ключ GigaChat настроен, но SYSTEM_LLM_SHARED_ACCESS выключен и список SYSTEM_LLM_ALLOWED_USERS пуст. Новый аккаунт должен добавить личное подключение либо получить индивидуальное разрешение администратора. Полный сценарий корректного каркаса GigaChat после изменения лимитов отдельно не подтверждён. Публикация новых изменений в Git не входила в эту проверку доступности.


По последующему прямому указанию владельца включён общий доступ SYSTEM_LLM_SHARED_ACCESS=1. Он сохранён в .env.docker релиза и в постоянном runtime.env на ВМ; backend/frontend пересозданы. Личные ключи не требуются для использования системной модели методистом. Суточную квоту организаторов (100 ₽ на команду) приложение отменить не может.
