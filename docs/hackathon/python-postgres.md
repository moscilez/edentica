# Python и PostgreSQL

Актуальный сервер — Python 3.12, FastAPI, Uvicorn, psycopg 3 с пулом соединений и PostgreSQL 18. Точка входа — `python -m backend`. `npm start` вызывает её через скрипт поиска Python. Интерфейс и адрес `http://localhost:3000/` сохранены.

## Установка на Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Существующий `.env` сохраняйте. Для новой установки скопируйте `.env.example`. Ключи и пароли не должны попадать в чат и репозиторий.

Если PostgreSQL уже настроен, задайте `DATABASE_URL` и используйте отдельную БД Edentica. Для отдельного локального экземпляра:

```powershell
npm run db:setup
```

Скрипт обнаруживает PostgreSQL в `C:\Program Files\PostgreSQL\18\bin` или через `POSTGRES_BIN`, создаёт кластер только в `data/postgres`, слушает `127.0.0.1:55432`, включает SCRAM и сохраняет случайный пароль в `.env`. Повторный вызов запускает существующий кластер. Другие экземпляры PostgreSQL не изменяются. После перезагрузки компьютера запускайте БД этой же командой.

Перед переходом остановите старый Node-сервер, чтобы он больше не записывал SQLite. Затем:

```powershell
npm run db:migrate
npm run start:local
```

Миграция читает согласованный SQLite-снимок, включая зафиксированный WAL, сохраняет резервную копию и переносит пользователей, сессии, блокировки, референсы, программы и события одной транзакцией. Формат scrypt сохранён: пользователи входят с прежними паролями. Действительные согласования сохраняются с пересчётом контрольной суммы после изменения порядка ключей JSONB; устаревшие требуют повторного утверждения. Остальные таблицы прежней LMS сохраняются в `legacy_records` как JSONB, исходный SQLite не удаляется. Повторный импорт идентичного снимка пропускается; существующие PostgreSQL-записи не перезаписываются. Исходные значения дополнительно сохраняются в JSONB-архиве. Миграцию выполняют при остановленном Python-сервере.

## Ответственность компонентов

| Компонент | Реализация |
|---|---|
| HTTP API, авторизация, защита запросов, статические файлы | Python / FastAPI |
| PostgreSQL, пул, транзакции, схема и импорт | Python / psycopg |
| Навыки агента, фоновые задачи, отмена и версии | Python / asyncio |
| Cloud.ru и проверка доступности источников | Python / httpx |
| Импорт документов, экспорт DOCX и GIFT | Python |
| Проверки часов, покрытия, шаблонов и инструкции навыков | Сохранённые чистые JS-модули через локальный subprocess без сети и БД |
| Веб-интерфейс | HTML / CSS / JavaScript |
| Экспорт PPTX | Python python-pptx; при наличии Codex runtime — существующий JS-экспортёр |

Рабочий Python-сервер не использует SQLite. Этот модуль используется только в одноразовом импорте. Прежние `server.mjs` и SQLite-модули сохранены для архивных тестов, в основном запуске они не участвуют.

Таблицы описаны в `backend/schema.sql`. Документ программы хранится в JSONB; события имеют последовательность IDENTITY и отдельный индекс. Внешние ключи связывают программы, пользователей и референсы. Время сессий хранится в BIGINT. Схема применяется при запуске; версия фиксируется в `schema_migrations`.

Пул содержит до восьми соединений; короткие SQL-операции выполняются через `asyncio.to_thread`, HTTP и subprocess работают асинхронно. Одновременно выполняются до двух задач генерации. Пользовательские изменения сериализуются по программе; запись проверяет владельца. Блокировка PostgreSQL не позволяет запустить второй планировщик на той же БД. Используйте **один Uvicorn worker**. Для нескольких реплик потребуется внешняя очередь заданий.

## Проверки и резервные копии

```powershell
npm test
npm run check
npm run test:legacy
npm run backup
```

Основные тесты используют настоящий PostgreSQL, создают отдельную БД с уникальным именем `edentica_test_*` и удаляют только её после прогона. Пользовательская база не очищается. Нужны права CREATE DATABASE; можно задать отдельный `TEST_DATABASE_URL`.

Проверяются авторизация, совместимость паролей, защита запросов, доступ к чужим данным, референсы, каркас и согласование, генерация с тестовым провайдером, точечная правка, экспорт, отмена и перезапуск, идемпотентность импорта. Реальных платных вызовов моделей тесты не делают.

`npm run backup` создаёт custom-format `pg_dump` в `data/backups` и проверяет каталог через `pg_restore --list`. Нужны PostgreSQL client tools версии сервера или новее (локально установлен комплект 18). Для восстановления в отдельную пустую БД используют `pg_restore`. Секрет передаётся процессу через окружение. Резервные копии содержат пользовательские данные и остаются локальными. Для Docker резервную копию можно делать штатным `pg_dump` внутри сервиса postgres.

## Docker

Используйте отдельный файл `.env.docker` по образцу `.env.docker.example`, затем `docker compose --env-file .env.docker up -d --build --wait`.
Полная инструкция для ВМ/VPS, IP, HTTPS и резервного копирования: [Docker](../docker.md).

Compose запускает PostgreSQL отдельно, ждёт его готовности и передаёт приложению адрес сервиса `postgres`. Данные БД и файлы приложения находятся в постоянных томах. Сервер запускается Python; Node нужен для существующих правил. Экспорт PPTX работает через python-pptx без библиотек Codex.

Реальную сборку/запуск контейнеров и развёртывание Cloud.ru нужно подтвердить на доступном Docker Engine. Визуальная проверка DOCX по страницам остаётся отдельной задачей.
