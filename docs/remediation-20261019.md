# Исправления требований и сквозного сценария

Изменения устраняют подтверждённые ошибки расчёта и исполнения, а не подменяют внешнюю оценку собственным баллом. Оценщик должен запускать рабочий Python backend и читать текущий контракт [workflow.md](workflow.md).

| Причина потери баллов | Изменение в рабочем коде | Проверка |
|---|---|---|
| В запросе есть ограничения, но они теряются после разбора моделью | Requirements, явный разбор часов/режима/практики/портфолио/слайдов, приоритет формы и ответов, происхождение значений. Придуманные моделью числа не становятся требованиями пользователя | Пять точных запросов и мутации ограничений в test_case_constraints.py |
| Неполный запрос автоматически считается достаточным | Нельзя угадать тип и объём; до пяти канонических вопросов. Ответы формы обрабатываются кодом без нового платного разбора | Кибербезопасность до и после ответов, API-тесты остановки перед согласованием |
| Несовместимый срок скрывается в календаре | До каркаса задаётся вопрос об изменении срока. Для 256 ч. при 4 ч./день показаны 64 учебных дня | Проверки 8/10/13 недель и дневного лимита |
| Календарные строки не являются занятиями | week/day и распределение часов allocations по темам. Одно занятие может включать несколько тем; длительность и периодичность проверяются независимо | 16 ч. = 8 × 2 ч., два раза в неделю, четыре недели; другие объёмы и режимы |
| Итоговая защита учитывается ещё раз в модулях | Подготовка отделяется от проведения аттестации до согласования; изменения видны в planningChanges. Готовый план с дублем проведения аттестации отклоняется | Отрицательные проверки экзамена и защиты в учебных модулях |
| Текст и таблицы считают часы независимо | canonical.py формирует числовые и основные формальные разделы из согласованного плана. В DOCX/UI отдельная колонка аттестации; суммы всех видов работы равны итогу | Чтение фактического DOCX и проверка каждой строки плана |
| Личные API или старые команды обходят правила | Один генератор уроков для workflow и старого API; режим hackathon проверяет endpoint и семейство модели до сети/расшифровки. Отказ Cloud.ru не включает другой провайдер | Запрет чужих API, старых подключений и несогласованной генерации |
| Реальная модель нарушает форму ответа | Динамические response_format JSON Schema с точными ID, числом вопросов/работ портфолио и обязательными полями. При неподдерживаемом формате — ограниченный переход к JSON, затем та же Python-валидация | Реальный шлюз принудительно выполнил схему; транспортные тесты и сквозные прогоны |
| Темы ссылаются на компетенции, определения которых модель пропустила | Отдельный навык дополняет только отсутствующие определения по связанным темам. Точные ID и полнота проверяются; существующие связи не переназначаются | Неизвестные и повторные ID отклоняются; исходные темы и определения сохраняются |
| Проверка требует буквальное название направления вместо связанных тем | Для кибербезопасности учитываются информационная и сетевая безопасность, защита данных; регистр названия понятия не влияет на проверку | План с реальными темами безопасности проходит; несвязанный курс Python отклоняется |
| Пропуск задания или ключа срывает весь комплект | Отдельные навыки лекции, оценивания, практического задания, теста, собеседования и итоговой аттестации. Дозапрашивается отсутствующая часть; готовые уроки и корректные разделы сохраняются | Сбой оценивания, отмена, перезапуск и продолжение без повторной лекции |
| Источники отсутствуют без поискового ключа | Тематическая первичная документация плюс ссылки референсов; поиск расширяется через BRAVE_SEARCH_API_KEY. Каждый HTTPS-редирект проходит новую сетевую проверку | Перенаправление документации Сбера, запрет HTTP/служебных сетей, явная маркировка недоступных страниц |
| Наличие номера принимается за проверенный профстандарт | Код и функция сверяются с документальными реквизитами; названия/URL/статус подставляет сервер. Подбор функции объясняется, область применимости остаётся за экспертом | Фальшивые коды, несовместимые функции, выдуманное ведомство и дата отклоняются |
| Отчёт проверяет только наличие полей | acceptance проверяет темы, режим, портфолио, собеседования, слайды и литературу с основаниями. Структурная связность не объявляется предметной экспертизой | Проверки неизвестных запросов и порчи готовых данных |
| Артефакты не соответствуют запросу слайдов | PPTX модулей и запрошенных занятий, manifest.json в ZIP; DOCX, JSON, GIFT и HTML-отчёт | Реальные выгрузки и проверка архива |
| Инструкция запуска противоречит архитектуре | Актуальные Docker/API/config инструкции, preflight проверяет PostgreSQL/Fernet/модель. Историческая Node LMS отделена от рабочего сценария | Изолированные PostgreSQL-тесты; Docker runtime не содержит Node или npm |

## Границы доказательств

Fixtures содержат входные запросы и тестовый транспорт, а не готовые ответы для пользователей. scripts/verify-case-matrix.py отдельно вызывает настоящую модель, сохраняет тайминги, токены, уточнения и артефакты. --resume явно помечает продолжение; его время нельзя выдавать за время генерации с нуля. Временная БД удаляется после прогона, пользовательские программы не затрагиваются.

Подтверждение существования источника, получение страницы, актуальность редакции и предметная применимость различаются. Метаданные известного документа не заменяют юридическую или педагогическую экспертизу. Недоступные ссылки и неподтверждённые коды видны в отчёте. Если упомянутый в запросе референс не загружен, агент сообщает об этом и использует стандартный шаблон.

Сервер по-прежнему рассчитан на один процесс backend: распределённой очереди нет. При аварийном перезапуске задание получает interrupted и продолжается человеком. Доступность и квота внешнего провайдера не гарантируются приложением. Внешние 429/5xx ограниченно повторяются, результат не подменяется заглушкой.

Локальная среда не имеет запущенного Docker Engine и LibreOffice: здесь нельзя считать подтверждёнными Docker rebuild или визуальный рендер страниц Word. Проверяются Python API/PostgreSQL, структура DOCX/PPTX/ZIP, арифметика таблиц и JavaScript редактора. Сборка Docker проверяется отдельно при развёртывании на ВМ.
